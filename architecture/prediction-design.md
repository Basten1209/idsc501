# 가격 방향 예측과 평가 설계

**설계 변경: 2026-10-15.** 가격과 소셜 데이터를 함께 사용해 다음 UTC 일별 종가의 상승·하락을 예측한다. OpenAI API는 핵심 추론 단계다. 이 문서는 구현 계약이며, 모델 호출·예측 정확도·운영 실적은 아직 없다. 화면의 예시 예측은 평가 데이터에 포함하지 않는다.

## 1. 예측 대상과 시각

| 항목 | 기본 계약 |
|---|---|
| 범위 | 가격 10종을 탐색하고, 소셜 범위가 설정된 DOGE·SHIB·PEPE·BONK·SPX 5종부터 예측 |
| 기준일 `d` | 방금 종료된 UTC 달력일. 기준 가격은 `close[d]` |
| 사건 마감 `event_cutoff` | `d+1 00:00 UTC` 미만의 가격·게시물만 사용 |
| 입력 동결 `input_cutoff` | `d+1 03:00 UTC`. 이때까지 실제 확보·검증된 관측만 사용 |
| 발행 기한 | `d+1 03:15 UTC`까지 저장된 예측만 전향 평가에 포함 |
| 예측 대상 | `close[d+1] > close[d]`이면 UP, 작으면 DOWN |
| 동일 종가 | 실제 라벨 FLAT으로 보관하고 UP/DOWN 정확도 분모에서 제외. 제외 수 보고 |
| 예측 보류 | 가격 누락·낡은 기준일·잘못된 응답·API 실패·발행 기한 초과는 방향 null과 상태 기록 |

예: 10월 15일 03:00에 입력을 동결하고, 10월 14일 종가보다 10월 15일 종가가 높을지 예측한다. 발행 시점부터 남은 예측 기간은 약 21시간이며, 정확히 24시간 수익률 예측이나 매수가 대비 수익률로 설명하지 않는다. 대상일의 장중 가격·게시물은 사용하지 않는다. UTC 경계가 확인된 CMC 일별 종가를 기준으로 하며 해당 일자가 이미 종료되어야 한다.

현재 제공 가격은 2026-10-07까지다. 새 CSV 공급 또는 CMC 크롤러 복원 없이 오늘의 예측을 발행하지 않는다. 월별 자료만 있으면 역사 탐색·재생 데모만 제공하고, 일별 예측 기능은 최신 가격·소셜 수집을 전제로 활성화한다.

## 2. 입력 구성과 시간 누출 방지

Python은 계산과 표본 선택을, 모델은 제공된 입력을 바탕으로 방향 판단과 짧은 근거 작성을 담당한다.

1. **가격:** `d`까지 연속 31개 유효 종가로 30개 수익률, 1·7일 수익률, 30일 변동성, 거래량 변화를 계산한다. 분모 0·누락·품질 이상을 명시한다. 입력에 사용한 정확한 가격 버전과 해시를 고정한다.
2. **소셜 수치:** 최근 7개 닫힌 UTC 날짜의 소스·cohort별 활동량, VADER 기초 감성, 유효 건수, 관측 반응 수와 커버리지를 사용한다. 서로 다른 모집단을 하나의 전체 언급량으로 합치지 않는다.
3. **소셜 본문:** 동일 7일 범위에서 검증된 코인 연결을 가진 원문을 플랫폼별 할당 후 최신순으로 최대 30건 선택한다. 동일 시각은 item_key로 정렬하고 각 본문은 최대 500자로 제한한다. 선택 규칙·제외 수·잘림 여부·snapshot ID를 기록한다. 밈 이미지는 초기 예측 입력에서 제외한다.
4. **시간:** 게시 시각만 확인하지 않는다. 선택한 observation의 `fetched_at`과 원본 확보 시각이 모두 `input_cutoff` 이하여야 한다. 늦게 확보한 글·수정 본문·반응 수를 과거 입력에 덮어쓰지 않는다. 사건 마감 전 게시물의 반응 수는 입력 마감까지 관측한 값으로만 표현한다.
5. **스냅샷:** 현재 `social_items`나 최신 daily mart를 과거 입력처럼 읽지 않는다. 마감 조건을 통과한 observations와 가격 버전으로 별도 입력 snapshot을 만든다. 원본 해시·관측 ID·파서/매칭/감성 버전·가용 시각을 manifest로 고정한다.

`fusion`은 설정된 활성 소셜 범위의 수집이 완료되고 유효 본문이 최소 1건일 때 발행한다. 미수집·오류·0건이면 fusion을 보류한다. 별도의 `price_only` 비교 예측은 가격 요건을 충족하면 발행할 수 있지만, 이를 가격+소셜 결과로 표시하지 않는다. 비활성 Reddit은 등록된 실험 범위에서 제외하고 X 기반 fusion임을 화면에 명시한다. 일부 필수 소스의 실패를 조용히 제외하지 않는다.

과거 가격·게시물의 날짜만 잘랐다고 당시 정보로 예측한 것은 아니다. 나중에 받은 아카이브는 `retrospective_replay`로 분리한다. LLM의 사전학습에 포함된 역사적 사건을 통제하기도 어려우므로 과거 재생은 파이프라인 동작 확인용이며, 주요 예측 평가는 **앞으로 발행하는 예측의 실제 결과**로 수행한다.

## 3. OpenAI API 호출과 결과 검증

서버의 Python 작업에서 Responses API와 지원 모델의 Structured Outputs를 사용하도록 설계한다. 구현 시 모델·SDK 버전을 확인하고 가능한 고정 모델 버전을 저장한다. 출력 구조의 준수와 예측의 정확성은 별도로 검증한다. [공식 구조화 출력 문서](https://developers.openai.com/api/docs/guides/structured-outputs)

모델 출력 계약은 `direction: UP|DOWN|ABSTAIN`, `rationale`, `topics`(최대 3개), `evidence_item_keys`, `limitations`다. 자산·대상일·마감 시각은 모델이 정하도록 하지 않고 요청 작업이 부여한다. 시스템은 enum, 길이, JSON Schema, 근거 ID가 입력에 실제 포함되었는지 검사한다. 근거는 제공한 자료에 대한 짧은 설명이며 내부 추론 과정이나 검증된 인과 설명으로 표시하지 않는다. 보정하지 않은 확신 수치를 성공 확률로 제공하지 않는다.

게시물은 신뢰할 수 없는 데이터로 구획하고 그 안의 명령을 따르지 않도록 한다. 모델의 웹 검색·코드 실행·DB 쓰기 도구는 연결하지 않는다. 본문에 포함된 투자 지시를 시스템 명령으로 취급하지 않고, 출처 URL은 텍스트와 함께 안전하게 표시한다. 모델 응답의 HTML을 실행하지 않는다.

응답 거부, 중단, timeout, 스키마 불일치, 알 수 없는 근거 ID는 실패/보류 상태다. 유효 응답이 없을 때 임의의 UP/DOWN을 채우지 않는다. 같은 요청 키 `(asset, target_date, variant, input_hash, model_version, prompt_version)`를 재실행하면 기존 성공 결과를 재사용한다. 재시도는 별도 attempt로 기록하고 최초 유효 발행 예측을 잠근다. 결과를 본 뒤 더 유리한 재시도 응답을 선택하지 않는다.

입력·응답 전문은 MongoDB `prediction_artifacts`, 정규화된 방향·근거 요약·식별 정보는 PostgreSQL에 저장한다. 호출량·토큰·비용·지연·request ID를 기록한다. OpenAI API 비용은 별도이며 무료 수집원과 구분한다. 구현 전 모델과 일별 예산 상한을 설정해야 한다. 5개 코인 × 2개 variant의 최대 10개 예정 예측/일을 기본으로 하고, 재시도 비용도 같은 예산에 포함한다. 화면 새로고침은 API를 호출하지 않는다. 이 문서 작업에서는 실제 유료 호출을 실행하지 않는다.

## 4. 평가와 피드백

예측 발행 이후 대상일의 가격이 확보되면 결과 평가 작업이 `prediction_outcomes`를 추가한다. 실제 가격이 아직 없으면 pending이다. 원래 예측과 입력은 수정하지 않는다. 가격 정정은 결과 버전을 추가하며 사용한 가격 observation을 연결한다.

| 비교 | 목적 |
|---|---|
| 직전 일 수익률 방향 유지 | 단순한 비LLM 기준선. 직전 수익률 0이면 보류 |
| 동일 모델·설정의 가격 전용 입력 | 소셜을 제외한 비교군 |
| 동일 모델·설정의 가격+소셜 입력 | 프로젝트의 주 예측 |

같은 코인·대상일, 같은 입력 마감과 유효 결과를 가진 쌍으로 비교한다. 정확도, balanced accuracy, UP/DOWN confusion matrix, 코인별 표본 수, 발행·보류·실패·FLAT 비율을 함께 보고한다. 한 클래스만 있으면 balanced accuracy를 계산하지 않는다. 공동 평가 집합과 전체 발행 coverage를 둘 다 표시해 쉬운 날만 남기는 효과를 드러낸다. 적중률을 투자 수익률로 바꾸어 설명하지 않는다.

설정 선택에는 시간 순서의 개발 구간을 사용하고, 마지막 연속 구간은 평가 때까지 고정한다. 같은 날짜의 모든 코인은 같은 구간에 배치한다. 모델·프롬프트 변경은 다음 실험 버전에만 적용한다. 기간과 샘플 수는 실제 확보량으로 보고하며, 수업 기간에 충분한 예측이 쌓이지 않으면 성능 결론을 유보한다. 시간 순서를 유지하는 평가 원칙은 [Forecasting: Principles and Practice](https://otexts.com/fpp3/toolbox.html)의 time series cross-validation을 참고한다.

피드백은 **실제 종가 → 결과 비교 → 팀의 오류 검토 → 다음 버전의 입력·프롬프트 변경**이다. 자동 재학습이나 자동 주문은 범위에 없다. 코인 매칭 오류, 소셜 공백, 근거 불일치, API 실패를 가격 방향 오류와 나누어 분석한다. [OpenAI 평가 지침](https://developers.openai.com/api/docs/guides/evaluation-best-practices)은 명시적 과제 기준과 반복 평가의 참고 자료이며 금융 예측 성능의 근거는 아니다.

## 5. 화면과 발표 표현

대시보드는 코인·기간 선택, 가격 차트, 다음 종가 방향, 예측 생성/대상 시각, 근거 게시물, 수집 범위, 과거 예측 결과를 보여준다. `live`, `historical replay`, `illustrative mockup`을 구별한다. 예시 UP 카드와 주제는 실제 모델 결과가 아니며, 아직 없는 성능 수치는 대시보드와 PPT에 넣지 않는다.

밈 패널은 출처를 표시한 관련 이미지 미리보기다. 문서와 별도로 미디어 표시 권한을 확인하고, 이미지 미수집/삭제 시 비워 둔다. 초기 모델 입력은 텍스트와 수치이며 밈 패널의 존재가 이미지 예측 분석을 의미하지 않는다.
