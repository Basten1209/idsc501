## 3. Why meme coins?

**55초 · 0:25–1:20**

이 차트는 제공받은 TRUMP의 전체 기간 일별 종가입니다. 처음 상승하는 구간은 우리가 기대하는 모습이고, 그 뒤는 “내가 사면 이렇게 된다”는 밈으로 표현했습니다. 실제 매매 결과를 보여 주는 것은 아닙니다.
가격 차트는 언제 움직였는지는 알려 주지만, 당시 커뮤니티에서 어떤 이야기가 오갔는지까지 보여 주지는 않습니다. 그래서 가격과 관측 가능한 게시물을 같은 시간축에서 살펴보고 싶었습니다. 사용자는 가격이 움직인 날짜를 선택하고, 관련 게시물과 당시 관측된 활동을 확인할 수 있습니다. 소셜 활동이 가격 변동의 원인이라고 단정하는 대신, 두 자료를 연결해서 맥락을 탐색하는 것이 목적입니다.
참고: 628개 종가, 최고 일별 종가 $45.5030010328, 마지막 제공 종가 $1.8772949946. 장중 최고가와 구분합니다.

## 4. Data overview

**40초 · 1:20–2:00**

데이터는 크게 두 종류입니다. 가격은 날짜별 숫자로 이루어진 정형 데이터이고, 소셜은 게시물 본문과 플랫폼별 메타데이터가 섞인 데이터입니다. 가격은 이미 10개 코인, 14,773행을 확보했습니다. 소셜 데이터는 이제 수집할 예정입니다.
X는 DOGE, SHIB, PEPE, BONK, SPX의 선정 계정부터 시작합니다. Reddit은 관련 커뮤니티를 대상으로 하되 접근 조건을 충족해야 합니다. 따라서 확보한 데이터와 수집 계획을 구분하고, 선정 계정의 활동을 전체 플랫폼의 언급량으로 해석하지 않겠습니다.

## 5. Data collection

**70초 · 2:00–3:10**

가격은 팀원이 CoinMarketCap Historical Data 페이지를 크롤링해 수집했고, 그 결과를 CSV로 전달받았습니다. CSV는 수집 방식이 아니라 수집 결과의 저장 형식입니다. 추가 갱신은 새 CSV를 받거나 팀원의 크롤러를 복원하는 방식으로 진행합니다.
X는 화면의 HTML을 직접 긁는 대신 FxTwitter의 제3자 API를 호출합니다. 선정 계정의 타임라인을 페이지별로 조회해 게시물과 반응 수가 담긴 JSON을 저장합니다. Reddit은 Arctic Shift의 커뮤니티·기간 검색 API 또는 필요한 월의 아카이브를 사용할 계획이며, 적용되는 접근과 사용 조건을 충족한 경우에 활성화합니다.
수집할 사이트와 소셜 채널은 팀이 선정합니다. MemeChain은 그 대상을 찾는 ideation에서 참고한 자료일 뿐 파이프라인에 적재하지 않습니다. 선정한 프로젝트 웹사이트는 링크와 계약 주소를 확인하는 데 크롤링으로 활용합니다. 소셜은 하루 한 번 수집하고 최근 7일을 다시 조회해 늦게 들어온 기록과 변경을 반영합니다.

## 6. Data preprocessing

**65초 · 3:10–4:15**

여기서는 게시물 한 건이 분석용 지표로 바뀌는 과정을 보여 드립니다. 왼쪽은 필드 구조를 설명하는 예시이며, 실제 수집한 게시물은 아닙니다. 먼저 원본 JSON을 보존하고, 게시물 ID를 기준으로 중복을 제거합니다. 게시 시각은 UTC로 통일하고, 반응 수를 관측한 시각과 구분합니다. 언어와 재게시 여부도 기록합니다.
그다음 검증한 계정과 코인 정보, 본문의 표현을 이용해 게시물을 코인에 연결합니다. 영어 텍스트에 대해서는 기본 감성 지표를 계산하고, 코인·날짜별 게시물 수와 평균 감성 등으로 집계합니다. 감성의 긍정·부정을 가격의 상승·하락 예측으로 해석하지 않습니다.
가격도 중복 날짜와 OHLC 관계, 0이나 누락 값을 점검합니다. 특히 API 실패는 활동 0건과 다릅니다. 수집을 확인한 경우에만 0을 쓰고, 실패나 미수집 상태는 결측과 상태 정보로 남깁니다.

## 7. Data pipeline & storage

**85초 · 4:15–5:40**

이 그림이 전체 데이터 파이프라인입니다. 왼쪽에서 오른쪽으로 수집, 원본 보존, 전처리, 저장과 변환, 화면 조회 순서로 읽으면 됩니다.
위쪽 가격 경로는 CoinMarketCap Historical Data 페이지를 크롤링한 CSV에서 시작합니다. 원본을 보존하고 날짜와 OHLC 관계 등을 점검한 뒤 PostgreSQL에 적재합니다.
아래쪽 소셜 경로는 선정 X 계정을 FxTwitter API로, 접근 조건을 충족한 Reddit 커뮤니티를 Arctic Shift로 수집합니다. 원본 JSON과 요청 URL, 수집 시각, 체크섬을 아카이브하고 ID와 시각, 플랫폼 필드를 표준화해 MongoDB에 저장합니다. 웹사이트 검증 응답이 있으면 HTML도 같은 아카이브에 보관합니다.
가운데 빨간 화살표가 두 DB 사이의 ETL입니다. MongoDB에서 코인 연결과 감성 등 필요한 값을 추출하고 코인·날짜·수집 범위별로 먼저 집계합니다. 이 결과를 PostgreSQL에 적재해 가격과 결합합니다. 검증된 분석 배치를 공개하고, Streamlit의 차트와 상태 화면은 이 SQL 결과를 읽습니다. 게시물 탐색에서는 SQL 투영으로 ID를 고른 뒤 MongoDB에서 상세를 조회합니다.
PostgreSQL도 JSON을 지원합니다. MongoDB는 소셜 문서를 따로 관리하고 문서형 모델과 관계형 모델 사이의 ETL을 구현하기 위한 선택이며, 두 DB의 운영 비용이 추가됩니다.

## 8. Dashboard & expected outcome

**50초 · 5:40–6:30**

최종 결과물은 이와 같은 대시보드입니다. 사용자는 코인과 기간을 선택해 가격과 소셜 활동을 비교하고, 특정 날짜에 관측된 게시물을 확인할 수 있습니다. 화면에는 수집 범위와 최신 관측 시각도 함께 보여 줍니다.
현재 왼쪽 DOGE 가격은 제공받은 실제 자료이고, 오른쪽 소셜은 아직 수집하지 않았기 때문에 빈 상태로 표시했습니다. 이것은 구현 예정 화면입니다. Streamlit과 Plotly로 만들고, 차트는 PostgreSQL에서, 게시물 상세는 MongoDB에서 조회할 계획입니다. 이 프로젝트를 통해 크롤링과 API 수집부터 전처리, SQL·NoSQL 저장, 실제 조회 화면까지 하나의 데이터 파이프라인을 구현하겠습니다.
